# Lee Relay v4.1 Blank-Slate Implementation Plan

**Goal:** Apply the latest Blank-Slate design to Lee Relay while preserving v4.0.1's background-tab relay, provider verification, Interactive mode, Full Auto mode, role/session/Loop Guard controls, and local export behavior. Ship v4.1.0 with persistent Rooms, Playbooks, bounded Runs, structured `@AI` handoffs, and durable Reports behind a simple side-panel UI.

**Architecture:** Keep the existing verified meeting/transaction pipeline as the provider boundary. Add pure domain modules for Workspace/Room persistence normalization, Playbooks, Runs/Budget, Mention routing, and Report generation. Adapt the background service worker at the storage and scheduling seams, retaining the existing serialized event queue and background-tab controller. Make the side panel consume a single combined state and reveal advanced settings progressively.

**Tech Stack:** Chrome MV3 extension, vanilla HTML/CSS/JS, ES modules, Node.js built-in `node:test`, local `chrome.storage.local`/`chrome.storage.session`, existing provider DOM adapters, deterministic local Markdown/TXT/JSON export.

**Spec:** `docs/superpowers/specs/2026-08-23-v4.1-blank-slate-design.md`

**Global Constraints:**

- Do not use Browse Code in this release.
- Do not change or bypass the verified delivery/response transaction semantics.
- Do not store live tab IDs, URLs, or transaction bindings in durable Rooms or Reports.
- Do not use shell write tricks; production and documentation edits use `apply_patch`.
- Use test-first RED/GREEN/REFACTOR for each behavior; keep the full 105-test baseline green.
- Preserve v3/v4 migration and the existing bcurts-inspired roles, sessions, routing, Loop Guard, and exports.
- Never force-push or destructively reset user data.
